# Which harness compiles the code it fuzzes, and which one only links it.
#
# The sanitizer flags in fuzz/CMakeLists.txt are PRIVATE on each executable.
# PRIVATE settings do not travel over a link, so they reach the harness's own
# translation units and stop there; the libraries are compiled without them. A
# harness that only LINKS the parser under test therefore fuzzes uninstrumented
# code: the undefined-behaviour checks never run at all, and the address checks
# see only what their interceptors see. A scalar read one past the end of a heap
# buffer -- which is what a length-driven walker does on hostile bytes -- is not
# reported. Nothing fails, and nothing was measured.
#
# This file is the one declaration of that, and it is read twice on purpose: by
# fuzz/CMakeLists.txt, which compiles what it names, and by
# ci/scripts/check-fuzz-instrumentation.sh, which reads the objects back and
# asserts they really carry the checks. Two hand-kept copies of one list is what
# cmake/EmrtdCryptoPrivateIncludes.cmake exists to prevent.
#
# Format, one row per harness and per source:
#   <harness>: <path/to/source.cpp>       repeat the harness for several sources
#   <harness>: LINK_ONLY  # <why> -- due YYYY-MM-DD
#
# A LINK_ONLY row with no written reason fails the check: "temporary" with no
# owner is how six of ten harnesses ended up in that state.
